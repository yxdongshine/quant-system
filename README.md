# 持仓纪律系统（quant-system）

> 解决的问题：**买点没问题，卖点下不了手。** 系统每天收盘后用分层仓位规则
> 给出 BASE（建底仓）/ ADD（加仓）/ SELL_ADD（卖加仓）/ EXIT（清仓）指令，
> 把卖出决策从情绪移交给规则 —— 信号收盘生成，次日开盘执行，盘中不看不动。

## 网页实时行情（2026-08-25 新增）

- 总览每张信号卡、个股 K 线页头部都会显示**实时价 + 涨跌幅**（A股配色：涨红跌绿），
  每 30 秒自动刷新一次，数据源为腾讯 `qt.gtimg.cn` 批量快照。

  防止盘中波动触发误导性买卖点），卡片上"收盘"标注的数字才是信号基准价。

## 分层仓位模型（底仓 / 加仓）（2026-08-25 新增）

针对"试探买入→上涨→顶部横盘舍不得卖→全部回吐"的行为病灶，系统把仓位拆成两层，
**加仓部分和底仓分开卖出**——走弱时只卖加仓锁定利润，底仓保留继续吃趋势；
趋势真正坏了才全清。没有加仓就不存在"舍不得卖"的问题。

| 信号 | 触发条件 | 动作（次日开盘） |
|---|---|---|
| **BASE 建底仓** | ST 翻多 且 收盘站上 60 日线 | 试探性建仓（实践中=先买1手） |
| **ADD 加仓** | 底仓浮盈≥5% 且 20日线上行 且 站上20日线 | 追加仓位（趋势确认） |
| **SELL_ADD 卖加仓** | 跌破 20日线<b>且均线下行</b> 或 触及吊灯线 | **只卖加仓部分**，底仓保留锁利 |
| **EXIT 清仓** | 收盘跌破 60 日线 | 全部卖出（含底仓），不讨价还价 |
| **HOLD 持有** | 多头结构完好 | 什么都不做 |

状态机：`空仓 → 底仓 → 底仓+加仓 →（走弱）→ 底仓 →（趋势坏）→ 空仓`

- 加仓门槛 `add_gain_min`（默认 5%）：底仓必须先盈利才允许加仓，杜绝在亏损中摊平；
- 再加仓须收复前次加仓价，防止横盘中反复被打脸；
- K线图标记：底=建底仓 · 加=加仓 · 减=卖加仓(保底仓) · 清=清仓；
- 参数 `add_gain_min` / `base_ratio` / `exit_mode` / `sell_add_strict` 可在 `params.json` 中手调；
- **v2 优化**（2026-08-25）：退出改为 MA60-only（不看 ST 翻空，减少噪音）、
  卖加仓改为严格模式（需 MA20 下行确认），回测三票平均收益较 v1 提升 ~33%。

## 每天怎么用（只有一步）

每个交易日 **15:20** 计划任务 `QuantDailyScan` 自动运行，打开当天报告即可：

```
quant-system\reports\signal_YYYY-MM-DD.md
```

报告按严重度排序（0=清仓 最紧急）。对应操作：

| 信号 | 含义 | 动作（次日开盘） |
|---|---|---|
| **EXIT 清仓** | 收盘跌破 60 日线 | 全部卖出，不讨价还价 |
| **SELL_ADD 卖加仓** | 跌破 20 日线且均线下行 或 触及吊灯止盈线 | 只卖加仓部分，底仓保留 |
| **ADD 加仓** | 底仓浮盈≥5% 且 20日线上行 | 追加仓位 |
| **BASE 建底仓** | ST 翻多 且 收盘站上 60 日线 | 试探性建仓 |
| **HOLD 持有** | 多头结构完好 | 什么都不做 |

手动补跑（任何时刻）：

```
cd /d D:\tool\ai\ecommerce-bigdata\quant-system
run_daily.bat           （或直接 python daily_scan.py）
```

## 文件结构

| 文件 | 职责 |
|---|---|
| `config.py` | 标的池（300750/300308/300502）+ 默认参数 |
| `datafeed.py` | 腾讯主源 + 东财备源（subprocess curl 绕 TLS 指纹风控），全量前复权，CSV 缓存于 `data/` |
| `indicators.py` | ATR(Wilder)/SuperTrend/吊灯止盈/唐奇安（纯 pandas） |
| `signals.py` | 信号规则：分层仓位状态机 BASE/ADD/SELL_ADD/EXIT + `tier_series` 序列 |
| `backtest.py` | 事件回测：分层仓位模拟（底仓+加仓、部分止盈、清仓全出，T+1 开盘执行，单边 0.1%） |
| `optimize.py` | 网格寻优 ST乘数×吊灯乘数，按 Calmar 选优并写入 params.json |
| `daily_scan.py` | 每日扫描入口，产出 `reports/signal_*.md` |
| `run_daily.bat` | 计划任务入口（写日志到 `logs/scan.log`） |
| `params.json` | **当前生效参数**（寻优自动更新，也可手改） |

## 当前参数与回测结论（2018 ~ 2026-08-24，前复权）

寻优结果：ST乘数=2.5，吊灯 ATR 乘数=4.0；v2 优化：退出=MA60-only、卖加仓=严格模式

| 股票 | 策略总收益 | BH总收益 | 策略回撤 | BH回撤 | 交易腿数 |
|---|---|---|---|---|---|
| 宁德时代 | +494.4% | +2040.6% | **-39.5%** | -66.5% | 82 |
| 中际旭创 | +1728.3% | +2569.5% | **-53.9%** | -67.8% | 82 |
| 新易盛 | +3428.1% | +13105.9% | **-52.5%** | -68.8% | 78 |

要点：v2（MA60-only退出+严格卖加仓）三票平均收益 +1884%，较 v1（+1459%）提升 29%。
最大回撤全部从 -67% 一带压缩到 -40% ~ -54%。
收益跑不赢 BH 是正常的（BH 是满仓死扛全程的幸存者视角），
本系统的目标是**让你在大跌里活着、拿住主升段、绝不当股东**。
胜率 28%~37% + 大盈亏比 = 趋势系统常态，单笔亏损是成本不是错误。

## 迭代模型（"边做边改"入口）

- **换/加标的**：改 `config.py` 的 `WATCHLIST`，跑 `python datafeed.py`
- **重新调参**：数据积累一段时间后跑 `python optimize.py`（自动更新 params.json）
- **验证新想法**：改 `signals.py` 的规则 → `python backtest.py` 对比报告
- **修改扫描时间**：
  `schtasks /Change /TN QuantDailyScan /ST 15:20`
- **删除任务**：
  `schtasks /Delete /TN QuantDailyScan /F`
